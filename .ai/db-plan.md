# PostgreSQL Database Schema - VibeTravels MVP

## 1. Tables

### `public.notes`

Stores user-created travel notes and AI-generated suggestions.

| Column Name       | Data Type      | Constraints & Defaults                                  | Description                                           |
|-------------------|----------------|---------------------------------------------------------|-------------------------------------------------------|
| `id`              | `uuid`         | `PRIMARY KEY`, `DEFAULT gen_random_uuid()`              | Unique identifier for the note.                       |
| `user_id`         | `uuid`         | `NOT NULL`, `FOREIGN KEY REFERENCES auth.users(id)`     | Identifier of the user who owns the note.             |
| `content`         | `varchar(5000)`| `CHECK (length(content) <= 5000)`                      | The text content of the note.                         |
| `is_ai_generated` | `boolean`      | `NOT NULL`, `DEFAULT false`                             | Flag indicating if the note was generated by AI.      |
| `created_at`      | `timestamptz`  | `NOT NULL`, `DEFAULT now()`                             | Timestamp when the note was created.                  |
| `updated_at`      | `timestamptz`  | `NOT NULL`, `DEFAULT now()`                             | Timestamp when the note was last updated.             |

### `public.profiles`

Stores additional user profile information, linked to Supabase Auth users.

| Column Name  | Data Type     | Constraints & Defaults                                  | Description                                      |
|--------------|---------------|---------------------------------------------------------|--------------------------------------------------|
| `id`         | `uuid`        | `PRIMARY KEY`, `REFERENCES auth.users(id) ON DELETE CASCADE` | User ID, references the Supabase auth user.      |
| `created_at` | `timestamptz` | `NOT NULL`, `DEFAULT now()`                             | Timestamp when the profile was created.          |
| `updated_at` | `timestamptz` | `NOT NULL`, `DEFAULT now()`                             | Timestamp when the profile was last updated.     |

## 2. Relationships

-   **`auth.users` (1) <-> (1) `public.profiles`**: Each Supabase Auth user has one profile. The relationship is established via `profiles.id` referencing `auth.users(id)` with `ON DELETE CASCADE`.
-   **`auth.users` (1) <-> (N) `public.notes`**: A user can have multiple notes. The relationship is established via the `notes.user_id` foreign key referencing `auth.users(id)`.

## 3. Indexes

-   `CREATE INDEX idx_notes_user_id ON public.notes (user_id);`
    -   Purpose: Optimizes fetching notes for a specific user.
-   `CREATE INDEX idx_notes_created_at ON public.notes (created_at DESC);`
    -   Purpose: Optimizes sorting notes by creation date (newest first), which is the default view.

## 4. PostgreSQL Functions & Triggers

### Function: `public.update_updated_at_column()`

```sql
CREATE OR REPLACE FUNCTION public.update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
   NEW.updated_at = now();
   RETURN NEW;
END;
$$ language 'plpgsql';
```
- Purpose: Automatically sets the `updated_at` column to the current timestamp.

### Trigger: `handle_updated_at`

```sql
CREATE TRIGGER handle_updated_at BEFORE UPDATE ON public.notes
  FOR EACH ROW EXECUTE PROCEDURE public.update_updated_at_column();
```
- Purpose: Executes the `update_updated_at_column` function before any update operation on the `notes` table.

### Trigger: `handle_profile_updated_at`

```sql
CREATE TRIGGER handle_profile_updated_at BEFORE UPDATE ON public.profiles
  FOR EACH ROW EXECUTE PROCEDURE public.update_updated_at_column();
```
- Purpose: Executes the `update_updated_at_column` function before any update operation on the `profiles` table.

## 5. Row Level Security (RLS) Policies

**Note:** RLS must be enabled for the tables first:
`ALTER TABLE public.notes ENABLE ROW LEVEL SECURITY;`
`ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;`

### Policies for `public.notes`

#### Policy 1.1: SELECT (Notes)

```sql
CREATE POLICY "Enable read access for own notes" ON public.notes
  AS PERMISSIVE FOR SELECT
  TO authenticated
  USING (auth.uid() = user_id);
```
- Allows authenticated users to read *all* notes (user-created and AI-generated) associated with their `user_id`.

#### Policy 1.2: INSERT (Notes)

```sql
CREATE POLICY "Enable insert for own non-AI notes" ON public.notes
  AS PERMISSIVE FOR INSERT
  TO authenticated
  WITH CHECK (auth.uid() = user_id AND is_ai_generated = false);
```
- Allows authenticated users to insert new notes only if `user_id` matches their own ID and `is_ai_generated` is `false`.

#### Policy 1.3: UPDATE (Notes)

```sql
CREATE POLICY "Enable update for own non-AI notes" ON public.notes
  AS PERMISSIVE FOR UPDATE
  TO authenticated
  USING (auth.uid() = user_id) -- Ensures they can only target rows they own
  WITH CHECK (auth.uid() = user_id AND is_ai_generated = false); -- Ensures they can only update non-AI notes
```
- Allows authenticated users to update notes only if `user_id` matches their own ID and `is_ai_generated` is `false`.

#### Policy 1.4: DELETE (Notes)

```sql
CREATE POLICY "Enable delete for own notes (including AI)" ON public.notes
  AS PERMISSIVE FOR DELETE
  TO authenticated
  USING (auth.uid() = user_id);
```
- Allows authenticated users to delete *any* note (user-created or AI-generated) associated with their `user_id`.

### Policies for `public.profiles`

#### Policy 2.1: SELECT (Profiles)

```sql
CREATE POLICY "Enable read access for own profile" ON public.profiles
  AS PERMISSIVE FOR SELECT
  TO authenticated
  USING (auth.uid() = id);
```
- Allows authenticated users to read their own profile.

## 6. Additional Notes

-   **Supabase Auth:** The schema relies heavily on Supabase's built-in authentication (`auth.users` table and `auth.uid()` function) for RLS.
-   **AI Note Insertion:** As per the planning session, inserting notes generated by AI (`is_ai_generated = true`) should be handled by a server-side mechanism (e.g., a Supabase Edge Function) using the Supabase `service_role` key. This key bypasses RLS policies, allowing the system to insert AI notes correctly associated with the user.
-   **Profiles Table:** A `profiles` table linked to `auth.users` has been added. For MVP, it stores minimal data (`created_at`, `updated_at`). Supabase can be configured to automatically create a profile entry when a new user signs up.
-   **Normalization:** The schema remains simple and appropriately normalized.
